# Note reader on real clinical text: protocol

> **Status: signed by Ahmed Zayed (MB BCh), 16 Nov 2026** ("Signed, make the sheet"), then changed by amendment 1 the
> same day, before any run. Changes after signature go under Amendments, dated.

## Why
The note reader (Qwen3-4B points to a sentence, `notas/verificar.py` checks it) has only seen synthetic notes. NHANES
has no notes, so the real-data trace marks this step "Not tested" ([`eval/results/nhanes_trace.md`](../eval/results/nhanes_trace.md)).

## Source (checked 16 Nov 2026)
**CodiEsp v1.4** (Zenodo record 3837305, doi:10.5281/zenodo.3837305, licence CC BY 4.0, open access): 3,751 Spanish
clinical case reports from open-access SciELO journals, written by clinicians about real patients and already
published. Not patient records, no direct identifiers, so it is not patient-derived data in the sense of our rules and
may be sent to the cloud runner. Downloaded file `codiesp.zip`, SHA-256
`52b290233906a2eb589ac7b1d9429adeac88f6a9cae8b0d3c180504afbe61688`.

Ruled out:
- **CARMEN-I** (real de-identified Hospital Clínic records) needs PhysioNet credentialing, a signed DUA and a review
  of each study by the contributor. It is patient-derived, and PhysioNet asks for local models or zero-retention cloud
  services, while our rule keeps patient data off the cloud and model weights off the laptop.
- **MIMIC**, for the same reasons, and it is in English.
- **SPACCC** (Zenodo 2560316, CC BY 4.0) comes from the same SciELO source; its overlap with CodiEsp is being checked.

What the source contains (regex counts over the 3,751 cases; a case can fall in several rows):

| Reader target | Cases |
|---|---|
| urine albumin (ACR, microalbuminuria, albuminuria) | 8, mostly in mg/24 h, not mg/g |
| a creatinine value in mg/dl | 249 |
| an eGFR or "filtrado" value | 30 |
| Nephrology mentioned | 57 |
| "rechaza", "no desea", "se niega" | 150 |

Honest limits of the source: these are hospital and specialist case reports, not primary-care notes. They rarely give
calendar dates ("al ingreso", "hace 3 años"), and urine albumin is almost absent. This makes the test a hard one:
real clinical prose full of numbers, units and traps (e.g. stool alpha-1 antitrypsin in mg/g), not a test of
finding ACRs.

## Question and primary measure
**Safety on real text:** per 100 notes, how many *verified* findings are wrong, i.e. the code accepts a finding that
the physician's label says is not there, or reads the wrong value, unit or person. A wrong verified finding is the
error that could change an order (wrongly confirm albuminuria, or wrongly treat a test as done). Reported with an
exact 95 % CI (Clopper-Pearson) and every case listed.

Secondary: how many labelled findings the reader returns and the code verifies (recall), split by target; how many
the code rejects and why (`motivo_rechazo`).

## Sample (superseded by amendment 1: 300 cases, no up-front labels)
100 cases, drawn with a fixed seed from the strata above: all albumin cases (8); 25 with a creatinine or eGFR value;
20 mentioning Nephrology; 17 with refusal words; 30 at random from the rest. Cases over 6,000 characters are cut by
`notas/leer.py` as in production; the label applies only to the part the model sees. Note date for every case: a
fixed placeholder (2026-06-01), stated, since case reports have no visit date.

## Labels (superseded by amendments 1–2: no up-front labels; accepted findings reviewed instead)
For each case Ahmed marks, using the reader's own categories (`notas/prompt_es.md`): `ya_realizada` with test, value,
unit and sentence number; `rechazo`; `nefrologia`; or `ninguna`. They are about the patient of the case only. A
labelling sheet with the numbered sentences is generated by a script; Ahmed fills it without seeing any model output.
Estimated time: about 1.5 min per case, so about 2.5 h for 100.

## Run
Qwen3-4B-Instruct-2507, the same prompt and settings as the recorded synthetic runs, on the existing Modal EU runner,
one call per case; outputs recorded to JSONL with a SHA-256 per note, so CI replays them without calling a model.
Spend: check 💳 Credits for Modal first; 100 short calls are expected to be small (to be measured, not assumed).

## What this does not show
That the reader works on Spanish primary-care notes. It shows how the code-verified output behaves on real Spanish
clinical prose. The primary-care test needs real primary-care notes (a research database application, listed under
"another month").

5. **16 Nov 2026, written before any labelling, signed with round 13 (`docs/FIRMA_VUELTA_13.md`, E1): reader recall.**
   On the 300 held-out cases (`muestra_heldout.json`), an AI agent (Claude Sonnet 5.5 sub-agent) reads each case
   text, numbered sentence by sentence with the same splitter the reader uses (`notas.verificar.frases`, the same
   6,000-character cut), **without seeing the model's output or the checks**. It marks every sentence that, by the
   definitions in this protocol, says (a) a kidney test (urine ACR / microalbuminuria, eGFR, serum creatinine) **was

   (not a single consult, referral or admission). Reference = the agent's marks. **Recall** = the share of marked
   (case, sentence, label) items for which the code accepted a finding with the same label on the same sentence,
   with an exact 95 % CI, per label and overall. Because the reader returns one finding per note, the **primary**
   recall is per note: of the notes with at least one marked item, the share in which the code accepted a finding
   that matches one of them (same label and sentence); per-item recall is descriptive. Also reported: the share the model pointed to at all (before the
   checks). Ahmed checks a random 20 of the marks (seed 20261119); if he changes any, the changed marks are used
   and the number of changes is reported. Limits: the reference is an AI agent of the same family as the system
   that wrote the checks, not a physician; the sample is hospital case reports enriched for kidney terms; serum
   creatinine counts as an eGFR finding, as in the reader's prompt ("creatinina en sangre"), and test-done findings
   are reported separately for CAC and FGe.

10. **16 Nov 2026, written before the blind set exists and before the round-15 code is run: blind test of round 15
   (`docs/FIRMA_VUELTA_15.md`, V1–V4).** No unseen real ACR text is left (every albumin case of CodiEsp and LivingNER
   is used; DisTEMIST, CANTEMIST and MedProcNER add none after de-duplication), so the test is a **blind adversarial
   set**. One AI agent (Claude Sonnet 5.5) writes about 150 one-sentence Spanish findings in the style of case-report
   lab lists. It works from a description of what each sentence clinically says, and **without reading `notas/`,
   `rules/`, `eval/` or any real case text**. For each sentence it writes the expected reading before any code runs:
   for the CAC, a value and unit, "normal" (no value), "unreadable" (ambiguous, unitless, a bound or two results), or
   "not an ACR" (dipstick, 24-hour, concentration, protein only); for the eGFR, a value or "bound". The set is
   committed before it is scored. Each sentence is scored as a one-sentence note, with the model's output simulated
   as pointing to that sentence and naming the expected test, on the code of `main` before round 15 and on the
   round-15 branch. **Primary (safety):** sentences where the code produces a reading that could act on the list and
   differs from the expected one: a wrong CAC value; a CAC value or a clean "normal" where the expected reading is
   unreadable or not an ACR; an eGFR value where a bound is expected. **Pass = 0 on the round-15 code.** **Secondary:**
   correct CAC values read (before vs after); sentences that are not an ACR but are accepted as a CAC (grey lines).
   Held-out 2 is replayed on both versions and reported as **tuning data, not a test**. Limits: synthetic sentences
   written by the same model family that wrote the code; they test the reading rules, not the model's pointing.
